# MOS.RU Water Meter

HACS-интеграция для Home Assistant: автоматически передаёт показания счётчиков воды на портал mos.ru в заданный день месяца.

Авторизация выполняется через QR-код — пароль вводить не нужно. Показания берутся из любых сенсоров Home Assistant с единицей измерения `м³`.

Работает через API [ed.mos.ru](https://ed.mos.ru/lk/counters/) («Электронный дом») — тот же сервис, через который показания передаются на сайте.

## Возможности

- Авторизация через QR-код (приложение mos.ru или Госуслуги Москвы), 2FA поддерживается автоматически
- Автоматическая отправка показаний в настраиваемый день месяца (по умолчанию 20-е)
- Поддержка любых HA-сенсоров воды (Waterius, ZigBee, WiFi и т.д.)
- Выбор счётчиков из личного кабинета через UI
- Ручная отправка кнопкой в любой момент
- Перезапись показаний за уже закрытый период — отдельным сервисом
- Сенсоры: текущие показания на портале, отправленные значения, статус, даты поверки, доступность отправки
- Уведомление о необходимости повторной авторизации при истечении сессии

## Установка через HACS

1. В HACS → **Custom repositories** добавьте:
   - URL: `https://github.com/kostinos/hass-mosru-water`
   - Category: `Integration`
2. Найдите **MOS.RU Water Meter** в HACS и установите
3. Перезапустите Home Assistant
4. Настройки → Устройства и службы → **Добавить интеграцию** → `MOS.RU Water Meter`

## Настройка

### Шаг 1 — Реквизиты
- **Код плательщика (ЕПД)** — 10-значный код из квитанции ЖКХ
- **Номер квартиры**

### Шаг 2 — QR-авторизация
В интерфейсе HA отобразится QR-код. Откройте приложение **mos.ru** или **Госуслуги Москвы**, нажмите кнопку сканирования QR и направьте камеру на экран. После сканирования авторизация завершится автоматически.

### Шаг 3 — Выбор счётчиков
Интеграция автоматически получает список ваших счётчиков. Выберите нужные для холодной и горячей воды.

### Шаг 4 — Источники показаний
- Выберите HA-сенсоры, откуда брать показания. Единица измерения должна быть `м³`
- Укажите день месяца для автоматической отправки (1–28)

## Как отправляются показания

Портал привязывает показание к расчётному месяцу и **не перезаписывает** уже внесённое значение: повторная отправка за тот же период отклоняется с ответом «Показание за данный период уже внесено».

Интеграция считает это нормальным состоянием, а не ошибкой: сенсор статуса покажет `already_submitted`, данные на портале останутся нетронутыми. Значение отправляется целым числом м³ — так требует портал.

Чтобы заменить уже внесённое показание, нужен явный вызов сервиса (см. ниже). Автоматика ничего не удаляет.

## Сервисы

| Сервис | Описание |
|--------|----------|
| `mosru_water.submit_now` | Отправить текущие показания. Если за период уже внесено — отправка не выполняется |
| `mosru_water.replace_readings` | Удалить последние показания на портале и отправить текущие |

### `mosru_water.replace_readings`

Нужен, когда показание за период уже внесено, а отправить требуется другое значение.

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `entry_id` | нет | ID записи интеграции. Можно не указывать, если настроена одна квартира |

> **Внимание.** Сервис удаляет **последнее** показание счётчика независимо от того, кто его внёс — оно могло прийти от управляющей компании, а не от интеграции. Поэтому удаление вынесено в отдельный сервис и никогда не выполняется автоматически.

```yaml
action: mosru_water.replace_readings
```

## Истечение сессии

Если сессия mos.ru истечёт, Home Assistant покажет уведомление «Требуется повторная авторизация». Нажмите на него и снова отсканируйте QR-код — больше ничего делать не нужно.

## Создаваемые сущности

Устройство **Водосчётчик ЖКУ &lt;код плательщика&gt;**, 13 сенсоров и кнопка. Точные `entity_id` зависят от имени устройства, ниже — отображаемые имена.

| Сущность | Описание |
|----------|----------|
| MOS.RU Холодная (mos.ru) | Текущее показание холодной воды на портале (м³) |
| MOS.RU Горячая (mos.ru) | Текущее показание горячей воды на портале (м³) |
| MOS.RU Холодная (отправлено) | Последнее значение, отправленное интеграцией (м³) |
| MOS.RU Горячая (отправлено) | Последнее значение, отправленное интеграцией (м³) |
| MOS.RU Статус отправки | `success` / `already_submitted` / `pending` |
| MOS.RU Последняя отправка | Дата и время последней отправки |
| MOS.RU Поверка холодного счётчика | Дата плановой поверки |
| MOS.RU Поверка горячего счётчика | Дата плановой поверки |
| MOS.RU Статус поверки холодного | Состояние поверки (`OK`, `EXPIRED`, …) |
| MOS.RU Статус поверки горячего | Состояние поверки |
| MOS.RU Период показания холодного | Расчётный период последнего показания на портале |
| MOS.RU Период показания горячего | Расчётный период последнего показания на портале |
| MOS.RU Отправка доступна | Принимает ли портал показания сейчас (`да` / `нет` / что заблокировано) |
| MOS.RU Отправить показания | Кнопка ручной отправки |

## Зависимости

- `requests >= 2.28`
- `qrcode >= 7.4`

## Разработка

Тесты не требуют Home Assistant и не обращаются к сети — сессия подменяется заглушкой, фикстуры взяты из реальных ответов портала.

```bash
python3 -m venv .venv
.venv/bin/pip install requests
.venv/bin/python -m unittest discover -s tests -v
```

Подробнее — в [tests/README.md](tests/README.md).

## Отказ от ответственности

Интеграция использует неофициальный API mos.ru. Работоспособность зависит от того, не изменил ли портал свой API.
