# MOS.RU Water Meter

HACS-интеграция для Home Assistant: автоматически передаёт показания счётчиков воды на портал mos.ru в заданный день месяца.

Авторизация выполняется через QR-код — пароль вводить не нужно. Показания берутся из любых сенсоров Home Assistant с единицей измерения `м³`.

Работает через API [ed.mos.ru](https://ed.mos.ru/lk/counters/) («Электронный дом») — тот же сервис, через который показания передаются на сайте.

## Возможности

- Авторизация через QR-код (приложение mos.ru или Госуслуги Москвы), 2FA поддерживается автоматически
- Автоматическая отправка показаний в настраиваемый день месяца (по умолчанию 20-е)
- Поддержка любых HA-сенсоров воды (Waterius, ZigBee, WiFi и т.д.)
- Выбор счётчиков из личного кабинета через UI
- Ручная отправка кнопкой в любой момент
- Перезапись показаний за уже закрытый период — отдельным сервисом
- Сенсоры: текущие показания на портале, отправленные значения, статус, даты поверки, доступность отправки
- Уведомление о необходимости повторной авторизации при истечении сессии
- Выход и повторный QR-вход без удаления интеграции и её настроек (с версии `2026.9.10`)

## Установка через HACS

1. В HACS → **Custom repositories** добавьте:
   - URL: `https://github.com/kostinos/hass-mosru-water`
   - Category: `Integration`
2. Найдите **MOS.RU Water Meter** в HACS и установите
3. Перезапустите Home Assistant
4. Настройки → Устройства и службы → **Добавить интеграцию** → `MOS.RU Water Meter`

## Настройка

### Шаг 1 — Реквизиты
- **Код плательщика (ЕПД)** — 10-значный код из квитанции ЖКХ
- **Номер квартиры**

### Шаг 2 — QR-авторизация
В интерфейсе HA отобразится QR-код. Откройте приложение **mos.ru** или **Госуслуги Москвы**, нажмите кнопку сканирования QR и направьте камеру на экран. После сканирования авторизация завершится автоматически.

### Шаг 3 — Выбор счётчиков
Интеграция автоматически получает список ваших счётчиков. Выберите нужные для холодной и горячей воды.

### Шаг 4 — Источники показаний
- Выберите HA-сенсоры, откуда брать показания. Единица измерения должна быть `м³`
- Укажите день месяца для автоматической отправки (1–28)

## Как отправляются показания

Портал привязывает показание к расчётному месяцу и **не перезаписывает** уже внесённое значение: повторная отправка за тот же период отклоняется с ответом «Показание за данный период уже внесено».

Интеграция считает это нормальным состоянием, а не ошибкой: сенсор статуса покажет `already_submitted`, данные на портале останутся нетронутыми. Значение отправляется целым числом м³ — так требует портал.

Чтобы заменить уже внесённое показание, нужен явный вызов сервиса (см. ниже). Автоматика ничего не удаляет.

## Сервисы

Обычная ручная отправка выполняется кнопкой **«MOS.RU Отправить показания»**. Для автоматизаций используйте `button.press` с фактическим `entity_id` этой кнопки.

| Сервис | Описание |
|--------|----------|
| `mosru_water.replace_readings` | Удалить последние показания на портале и отправить текущие |

### `mosru_water.replace_readings`

Нужен, когда показание за период уже внесено, а отправить требуется другое значение.

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `entry_id` | нет | ID записи интеграции. Можно не указывать, если настроена одна квартира |
| `confirm` | да | `true` — явно подтвердить удаление последних показаний |

Сервис доступен администраторам HA и доверенным внутренним автоматизациям.

> **Внимание.** Сервис удаляет **последнее** показание счётчика независимо от того, кто его внёс — оно могло прийти от управляющей компании, а не от интеграции. Поэтому удаление вынесено в отдельный сервис и никогда не выполняется автоматически.

```yaml
action: mosru_water.replace_readings
data:
  confirm: true
```

Перед записью проверяются оба счётчика выбранной квартиры и оба источника.
Сенсоры должны быть разными, возвращать конечное неотрицательное значение в
`m³` и иметь сообщение не старше 48 часов (`last_reported`, либо `last_updated`).
Значения округляются до целых м³; именно эти числа сохраняются как отправленные.
Показание не должно уменьшаться или превышать последнее показание портала более
чем на 100 м³. Аномальные значения нужно проверить и внести вручную на mos.ru.
Замена разрешена только для доступных для записи счётчиков с последним показанием
текущего месяца. Показания прошлых периодов интеграция не удаляет.

Операции с сессией не пересекаются, а повторная запись возможна не чаще раза в
минуту. DELETE и PUT не образуют транзакцию на портале: при сбое статус `partial`
и атрибут `operations` показывают подтверждённые и неопределённые этапы.
Автоматика приостанавливается до конца месяца, включая после перезапуска HA.
После проверки портала успешная ручная отправка снимает блокировку. Удаление
никогда не повторяется автоматически; исправление вниз и восстановление после
неопределённого удаления выполняются на самом портале.

QR-файлы имеют случайные адреса и удаляются после завершения/отмены входа и при
обновлении QR. После аварийного завершения старые файлы удаляются при следующем
входе. `/local` остаётся публичным: не распространяйте ссылку на активный QR.
HTTP-клиент проверяет HTTPS и узел каждого перехода (login/www/ed/my.mos.ru),
ограничивает ответ 2 MB и не использует прокси из переменных окружения.
Логи не содержат содержимое HTML входа и параметры OAuth-редиректов.

Сессионные cookies по-прежнему являются секретами в config entry. Используйте
шифрование резервных копий HA и не публикуйте `.storage` или cookies.
Идентификаторы в тестах синтетические; прежние коммиты могут содержать старые
HAR-фикстуры, историю Git это изменение не переписывает.

## Автоматическое обновление сессии

С версии `2026.9.11` интеграция проверяет данные каждые 45 минут и автоматически
обновляет авторизацию «Электронного дома» через действующую сессию mos.ru.
Cookie `Authorization` у ed.mos.ru живёт один час независимо от `acst`;
кеш авторизации переиспользуется не дольше 40 минут. Новый вход выполняется
при следующем обращении к API после этого срока, обычно на 45-й минуте.

Если чтение счётчиков вернуло отказ авторизации раньше срока, интеграция один
раз обновит сессию и повторит чтение. Отправка и удаление показаний таким
способом не повторяются. Тайм-ауты и временные ошибки сервера не запускают QR-вход.

Если сессия mos.ru истекла или восстановление авторизации отклонено, Home Assistant
предложит повторный вход через QR. Обновление не обходит ограничения профиля
портала, например проверку возраста.

## Выход и повторный вход без удаления интеграции

В **Настройки → Устройства и службы → MOS.RU Water Meter → Настроить** выберите
**«Выйти и войти заново»** и подтвердите выход. Интеграция остановится и удалит
свою сохранённую сессию. Откройте запрос повторной авторизации на странице
интеграции или уведомление MOS.RU Water и пройдите вход через QR-код.

Реквизиты, счётчики, сенсоры и день отправки сохраняются. До завершения входа
обновления и отправка показаний не выполняются. Выход не завершает сессии mos.ru
в браузере и на других устройствах. Если Home Assistant будет перезапущен до
завершения входа, он снова предложит авторизацию.

## Ошибка авторизации HTTP 451

При сообщении `ed.mos.ru auth: HTTP 451` сервис «Электронный дом» может отклонять вход из-за проверки возраста. В подтверждённом случае API сообщил, что сервис доступен пользователям старше 18 лет и предложил проверить дату рождения в профиле mos.ru. Сам код 451 без текста ответа не определяет причину.

Проверьте дату рождения в профиле [mos.ru](https://www.mos.ru/), затем попробуйте войти в [Электронный дом](https://ed.mos.ru/) под той же учётной записью. После исправления данных можно выполнить «Выйти и войти заново» в настройках интеграции. Повторный вход сам по себе не снимает ограничение сервиса. Если дата верна, а ошибка сохраняется, обратитесь в поддержку портала.

## Создаваемые сущности

Устройство **Водосчётчик ЖКУ &lt;код плательщика&gt;**, 13 сенсоров и кнопка. Точные `entity_id` зависят от имени устройства, ниже — отображаемые имена.

| Сущность | Описание |
|----------|----------|
| MOS.RU Холодная (mos.ru) | Текущее показание холодной воды на портале (м³) |
| MOS.RU Горячая (mos.ru) | Текущее показание горячей воды на портале (м³) |
| MOS.RU Холодная (отправлено) | Последнее значение, отправленное интеграцией (м³) |
| MOS.RU Горячая (отправлено) | Последнее значение, отправленное интеграцией (м³) |
| MOS.RU Статус отправки | `success` / `already_submitted` / `pending` |
| MOS.RU Последняя отправка | Дата и время последней отправки |
| MOS.RU Поверка холодного счётчика | Дата плановой поверки |
| MOS.RU Поверка горячего счётчика | Дата плановой поверки |
| MOS.RU Статус поверки холодного | Состояние поверки (`OK`, `EXPIRED`, …) |
| MOS.RU Статус поверки горячего | Состояние поверки |
| MOS.RU Период показания холодного | Расчётный период последнего показания на портале |
| MOS.RU Период показания горячего | Расчётный период последнего показания на портале |
| MOS.RU Отправка доступна | Принимает ли портал показания сейчас (`да` / `нет` / что заблокировано) |
| MOS.RU Отправить показания | Кнопка ручной отправки |

## Зависимости

- `requests >= 2.28`
- `qrcode >= 7.4`

## Разработка

Тесты не требуют Home Assistant и не обращаются к сети — сессия подменяется заглушкой, фикстуры взяты из реальных ответов портала.

```bash
python3 -m venv .venv
.venv/bin/pip install requests
.venv/bin/python -m unittest discover -s tests -v
```

Подробнее — в [tests/README.md](tests/README.md).

## Отказ от ответственности

Интеграция использует неофициальный API mos.ru. Работоспособность зависит от того, не изменил ли портал свой API.
